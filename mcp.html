What is Model Context Protocol (MCP)?

Updated April 2026 · 3 min read

My takeaway

MCP is like a USB-C port for AI — a single standard that lets any model connect to any tool. Instead of building one-off integrations, you plug in once and everything works.

What problem does it solve?

Before MCP, if you wanted an AI model to access your files, search the web, or query a database, someone had to build a custom connection for each combination. It was messy, fragmented, and hard to maintain.

MCP — Model Context Protocol — is Anthropic's open standard that creates a common interface between AI models and external tools or data sources. Build a connector once, and any MCP-compatible model can use it.

How I think about it

Think of it in layers. The AI model (like Claude) is the brain. MCP servers are the connectors — each one gives the model access to something new: a Google Drive, a database, a calendar. The MCP client (like Claude.ai or an app you build) is what ties them together.

A good analogy: MCP is to AI tools what HTTP is to the web. A shared protocol that makes everything interoperable.

Why it matters for product people

As a PM, what excites me about MCP is that it dramatically lowers the cost of building AI-powered features. Instead of negotiating custom integrations for every data source, teams can plug into a growing ecosystem of ready-made connectors.

It also means AI agents can actually do things — not just answer questions, but take actions across tools. That's a fundamental shift in what's possible to build.

What I'm still exploring

I'm currently looking at how MCP works in practice with Claude Code — how you set up servers locally and what kinds of workflows become possible when your AI assistant can read and write to your own files and apps.
