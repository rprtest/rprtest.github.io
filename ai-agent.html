What is an AI agent?

Updated April 2026 · 3 min read

My takeaway

An AI agent isn't just a chatbot — it's an AI that can plan, take actions, and loop until a task is done. The shift from "answering questions" to "getting things done" changes everything about how we build products.

Chat vs. agent — what's the difference?

A regular AI interaction is a single exchange: you ask, it answers. An AI agent is different — it takes a goal, breaks it into steps, executes those steps (often using tools), checks the results, and keeps going until the job is done.

The key ingredient is autonomy over multiple steps. The model isn't just generating text — it's making decisions, calling tools, reading results, and adapting.

Simple way to think about it: a chatbot answers your question. An agent completes your task.

What makes an agent an agent?

Three things tend to define an agent: it has a goal to work towards, it has access to tools (search, code execution, file access, APIs), and it operates in a loop — acting, observing results, and deciding what to do next.

This loop is sometimes called a "ReAct" pattern — the model reasons about what to do, acts, and then reflects on the result before taking the next step.

Why this matters for PMs

As someone who builds products, the agent shift is significant. Features that used to require building custom automation pipelines can now be described in plain language and delegated to an agent. That changes what's feasible to build — and how fast you can build it.

It also raises new product questions: how much autonomy do you give the agent? When does it ask for confirmation? How do users stay in control? These are deeply product and UX problems, not just engineering ones.

What I'm still figuring out

I'm exploring how agents handle failure gracefully — what happens when a tool call doesn't work or the task is ambiguous. That gap between "it works in a demo" and "it works reliably in production" is where the most interesting product design happens.
